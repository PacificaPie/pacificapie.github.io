A job search keeps going after the search ends

Finding a relevant opening starts another sequence of work: checking the role, locating the application, collecting personal information, filling out forms, and tracking what happened. Across repeated sessions, the same context has to survive. I wanted a workflow that could carry a role through these steps and pick up where it stopped.

Three tools, with explicit responsibilities

The current system uses Codex for discovery, Notion for shared state and information, and Muse for application execution. Codex can also attempt applications. The useful design question is how these tools hand work to one another and recognize the result.

  1. Codex — find and assess roles. Use web search to recall relevant openings, consult the profile and existing roles in Notion to find similar opportunities, and attempt applications where possible.
  2. Notion — hold the workflow's memory. Keep the job database, application state, and personal information together. Codex uses this context for matching; Muse uses the same information to fill applications.
  3. Muse — carry out applications. Read the relevant information, fill out the application, and submit it. If a step needs my judgment or missing information, preserve it as unfinished work.

搜索结束以后，求职才刚开始

找到一个合适的岗位，后面还有一串工作：判断是否匹配、找投递入口、整理个人资料、填写表单，再记录到底投到了哪一步。这些事会反复发生，也经常跨越不同的对话和网站。我想做的是让一个岗位能沿着这条链路往前走，中间停下以后也能继续。

三个工具，各自承担一部分工作

现在的架构是 Codex 负责召回，Notion 承担状态和信息，Muse 负责实际投递。Codex 也会尝试投递。这里需要设计的是分工、任务交接，以及怎样判断一次执行有没有完成。

  1. Codex：找到并判断岗位。 通过 web search 召回岗位，调用 Notion 里的个人信息与已有岗位寻找相似机会，并在可执行的环节尝试投递。
  2. Notion：保存流程的记忆。 同时承担岗位数据库、状态机和个人信息库。Codex 用它辅助匹配，Muse 读取同一份资料用于填写申请。
  3. Muse：完成投递动作。 读取相关资料，填写并提交申请。需要我判断或者补充信息的地方，保留成后续可以继续处理的任务。

What I designed

My work centers on the task boundaries, the information each step needs, and the criteria for moving to the next state. Notion makes the context available across tools. A role discovered by Codex can carry its source and matching context forward; Muse can use the personal information without asking me to reconstruct it for every form.

An attempted action and a completed application need distinct records. A blocked step needs enough context to resume it. These decisions determine whether the workflow is useful over time.

How I judge the workflow

  • Traceable discovery: a role has a source and an application entry that can be checked.
  • Consistent information: matching and form filling use the same personal information.
  • Verifiable completion: an application is recorded as submitted only with an official confirmation or receipt; unfinished attempts stay visible for follow-up.

A related implementation, Reachout in the public repository, covers role discovery, evaluation, and application preparation with manual submission. This page describes my personal workflow with Codex, Notion, and Muse.

我具体设计了什么

我的工作集中在任务边界、每一步需要的信息，以及进入下一个状态的条件。Notion 让上下文可以在工具之间继续使用：Codex 找到的岗位可以带着来源和匹配依据往下走，Muse 填表时也可以直接使用个人资料，减少每次重新提供信息的工作。

尝试过一个动作，和完成一次投递，需要留下不同的记录。中途卡住的环节，也要保留足够的信息才能继续。这些设计决定了这个流程能不能长期使用。

我用什么判断这条链路是否成立

  • 召回可回看：岗位有明确来源，投递入口可以核对。
  • 资料一致：岗位匹配和表单填写使用同一份个人信息。
  • 完成可确认：拿到官方确认或回执后才记为已投；没有完成的尝试继续保留，方便后续处理。
