“Keep Tuesday afternoon free. What if I take more programming?”

Course planning starts with a mix of requirements, interests, and half-formed preferences. The difficult part comes when one of them changes: which plan are we editing, what must stay fixed, and which earlier result can we still trust?

I built this prototype around that revision loop. A host AI can turn the conversation into structured inputs; MCP tools search the public CourseTable catalog, check explicit constraints, and save separate plans. The output is a combination to compare and a shared worksheet to preview, with unresolved checks kept alongside it.

“周二下午别排课。但如果我想多学一点编程呢？”

选课的起点往往是混在一起的要求、兴趣和还没想清楚的偏好。真正麻烦的是改主意之后：现在改的是哪份方案，哪些条件还要保留，之前算出来的结果还能不能用？

我围绕这轮反复修改做了一个原型。宿主 AI 将对话整理成结构化输入，MCP 工具查询 CourseTable 公开课程、检查明确约束，并分别保存不同方案。最终交付可以比较的课程组合和共享课表预览，同时保留仍需核实的事项。

Give each part a clear responsibility让理解、检查和记忆各有归属

Host AI宿主 AI

Handles the conversation, interprets materials, asks for clarification, and explains tradeoffs. Those abilities come from the host; the MCP server does not call a model itself. Full conversation and attachment handling still need validation.负责对话、理解材料、澄清偏好和解释取舍。这些能力来自宿主，MCP 服务本身不调用模型；完整对话和附件理解仍需单独验证。

Planning tools规划工具

Search a public catalog snapshot and solve within an explicit candidate pool. Check known class times, fixed courses, credits, and excluded time slots; rank supported soft preferences such as avoiding early classes.查询公开目录快照，在明确候选池内求解。检查已知上课时间、固定课程、学分和禁排时段，再按照避开早课等已支持的软偏好排序。

Persistent state持久化状态

SQLite stores the student profile, separate scenarios, and historical results. Each result is tied to its inputs. A changed profile, plan, or catalog makes an old result stale and requires a new solve before export.SQLite 保存学生档案、独立方案和历史结果。每次结果绑定当时的输入；档案、方案或目录发生变化后，旧结果会失效，需要重新求解才能导出。

The product work is in what happens after a change

My focus is turning an open-ended planning task into explicit operations: confirm a background fact, update one scenario, fork another direction, compare results, and choose a specific combination to preview. Persistent state makes those decisions available beyond a single conversation.

That also defines how I evaluate the system. Updating B must leave A unchanged. A newly confirmed fact must invalidate incompatible old results. A plan with no solution must stay unsolved until someone changes a condition. And a planned course must never silently become a completed prerequisite.

What the prototype has demonstrated

The recorded demo uses public courses and a fictional student to complete profile storage, course search, A/B branching, comparison, and worksheet export through a real MCP service. It also checks state recovery after reconnection and rejection of stale exports.

A separate evaluation journey covers ten checkpoints, with eight automated backend checks. Natural-language extraction, ambiguous references, explanations, and real attachments require a separate host-AI evaluation; the protocol demo does not establish that full experience.

Next: make the planning loop visible

The next product step is a frontend where students can see the constraints they have confirmed, compare A and B, edit the right plan, and understand why a result needs recalculation. Pending checks should remain visible next to the worksheet preview.

Real student trials will help test that experience. Today the prototype uses public catalog snapshots and shared previews; account sign-in, private evaluations, registration writes, live seat availability, and a complete degree audit are outside the implemented scope.

产品设计，落在每次改动之后会发生什么

我的重点是把开放式的选课任务拆成明确操作：确认一项背景信息、修改某个方案、复制另一条方向、比较结果，再选择具体组合打开预览。持久化状态让这些决定可以跨会话继续使用。

这也决定了评测要看什么。修改 B 时，A 应该保持原样；确认新信息后，不再适用的旧结果应该失效；条件无解时，需要先改变条件才能继续；“计划修读”的课程，不能悄悄变成“已经完成”的先修课。

原型目前验证了什么

现有演示使用公开课程与虚构学生，通过真实 MCP 服务跑通了档案保存、查课、A/B 分支、方案比较和课表预览导出，也检查了断开重连后的状态恢复，以及旧结果导出被拒绝的情况。

此外，完整选课旅程被拆成十个评测检查点，其中八项可以通过后端自动检查。自然语言提取、模糊指代、解释和真实附件仍需在宿主 AI 中单独评测；协议演示还不能证明完整对话体验已经成立。

下一步，把这轮修改变成看得见的体验

前端会围绕学生真正需要判断的内容继续打磨：已经确认了哪些条件，A 和 B 有什么区别，当前改的是哪份方案，为什么要重新计算。仍需核实的事项也应和课表预览放在一起。

接下来会用真实学生试用来检验这些设计。当前原型使用公开课程快照和共享预览，尚未接入账号登录、私有评价或注册写入，也不覆盖实时余量与完整学位审计。
